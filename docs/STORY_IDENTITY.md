# Исследование ID сюжетного мира

Текущий статус: **источник текущей миссии/checkpoint для сети не подтверждён**.
Локальная epoch, последняя запись на диске и совпадение каталога ресурсов не
заменяют согласованный идентификатор сюжетного состояния двух клиентов.

## Отвергнутые интерпретации

- GameBase +0x0c — уже исследованный буфер запроса StartGame. Он может быть
  пуст во время миссии и не должен становиться текущим ID.
- Четыре строковых поля CGame +0x0c/+0x10/+0x14/+0x18 — корни ресурсов карты,
  а не имя главы. На pinned GOG image CGame vtable slot +0x14 указывает на
  0x5cd760. Этот Open форматирует `/games/%s.bin` и загружает буфер в +0x2c.
  Ветка 0x5c90db..0x5c911d парсера 0x5c9090 сохраняет указатели на четыре
  последовательные NUL-строки chunk 0xe001 в эти поля.
- Локально проверенный FirstCity game-map из tables.sds имеет GMP version 6:
  четыре строки задают корни City/Shops/Traffic/Cars. Другой menu game-map
  содержит четыре корня `/`. Это не доказательство текущего номера главы.
- PLAYING_CHAPTER встречается в преобразовании строкового имени в номер поля
  (0x44cf40), но само наличие этого имени ещё не даёт значение текущей главы.

## Следующий кандидат: save/load-интерфейс

0xb2d230 возвращает **адрес объекта** 0x1cc395c, а не указатель, хранящийся по
этому адресу. Метод 0xb2c690 возвращает DWORD из this+0x68. Прямой вызов в
0xb4058f..0xb40594 использует именно этот interface address. Возвращённое
значение передаётся другому интерфейсу, связанному со штатным save/load-путём.
Точное значение, свежесть после загрузки и принадлежность checkpoint пока не
доказаны. У соседнего основного объекта другой this; не переносить offsets
между ним и interface subobject без проверки adjustor/call site.

`scripts/inspect_runtime.py` теперь записывает значение этого поля и его
совпадение с уже прочитанными ID каталога сохранений в частный отчёт. Это только
**кандидат**; совпадение не включает сетевую синхронизацию и не устанавливает
identity_verified. В консоль выводятся только флаги и статус проверки, без
самого значения, указателей и строк ресурсов.

Для полей карты проверяются open-bit CGame, GMP magic/version/chunk, размер до
4096 байт, четыре точных указателя внутрь payload, NUL-окончания и ASCII-корни.
Старые/нечитаемые/несовпадающие поля не интерпретируются как готовая карта.
Все чтения выполняются снаружи процесса только после существующей проверки
полного EXE SHA256. Никаких game API calls, инъекции или записей в память.

## Что ещё нужно проверить

1. Снять candidate до загрузки, после штатного меню-запуска, после checkpoint,
   после провала/восстановления, в другой главе и после возврата в меню.
2. Сопоставить динамику с реальным mission/checkpoint и native save/load-кодом;
   исключить pending request, stale value и общий для нескольких глав game-map.
3. Только после этого определить сетевой world ID и host transition generation,
   а затем реализовать подтверждение совпадения обоими игровыми клиентами.

Пока игровая проверка ввода ограничена описанным в INPUT_DIAGNOSTIC.md путём.
Добавленный тест story_audit использует искусственную память только для
проверки границ чтения; он не является вторым клиентом или приёмкой миссии.
