# Чтение состояния сюжетного игрока

`src/game/telemetry.c` — первый read-only адаптер, а не синхронизация или создание удалённого игрока. Он работает только под проверкой SHA256 наблюдателя для текущего GOG EXE.

## Проверенная цепочка

- Singleton CGame: `0x1ABFE14`, поле local ped `+0x118` из ICGame. Указатель и все последующие поля перечитываются при каждом снимке.
- Virtual GetPosition по `vtable+0x8C` реального сюжетного игрока: `0x938250`. Дизассемблирование показывает ветвление по `player+0x190`: физическое представление или координаты модели.
- У физического представления getter `vtable+0x54` в тесте равен `0x18AE690`. Его полная реализация возвращает `this+0x1D8`, без записи. Адаптер читает эти три float напрямую и не вызывает игровой код.
- Координаты модели по `player+0x60`, затем `+0x44/+0x54/+0x64` читаются отдельно для сравнения; они не заменяют физическую позицию.
- GUID по `player+0x1C` — локальный идентификатор сущности. Он не используется как общий ID между компьютерами.

При иной реализации getter, отсутствии объектов, нечитаемой памяти или нечисловых координатах снимок отклоняется. Не включён автоматический переход на другие offsets. Текущая цепочка не считается проверенной для транспорта, смерти, всех глав и кат-сцен.

## Жизненный цикл

Регистрация остаётся в одном проверенном игровом callback. `mission_open` создаёт новую локальную epoch; это номер поколения, **не номер главы**. После обоих событий `game_init` и `load_finished` снимки читаются на `tick` с частотой до 2 Гц для диагностики. `load_started` запрещает снимки до `load_finished`; `game_done`, `mission_before_close`, `mission_close` и `shutdown` сбрасывают готовность. Указатели не сохраняются между кадрами. Сетевой частоты обновлений и удалённого применения состояния ещё нет.

Журнал остаётся локально. `scripts/summarize_telemetry.py <private probe.log>` проверяет порядок жизненного цикла, epoch, время, конечность координат и общий поток reader/callback. Печатаются только число снимков и диапазоны изменения координат; личные пути и сами координаты не выводятся. Отсутствие снимков считается ошибкой, а не успешной проверкой.

## Фактические результаты

Внешнее read-only наблюдение движущегося игрока в миссии: 75 снимков за 15 секунд, один GUID, диапазоны изменения X/Y/Z — 17.643 / 12.210 / 0.988 игровых единиц. Это подтверждение изменения наблюдаемой позиции после просьбы пользователю двигаться, не доказательство сетевой синхронизации.

Первый внутрипроцессный адаптер действительно получил снимки в игровом callback. Проверка выявила временную нулевую позицию до load_finished; готовность только по game_init была недостаточна. Исправленный адаптер ожидает оба события. Сборка и 8 интеграционных проверок загрузчика прошли; анализатор также проверен на корректном движении и 7 видах неверного свидетельства. Новая игровая проверка исправленного варианта ещё не выполнена: текущий тестовый процесс оставлен пользователю для обычного выхода. Нужны два последовательных запуска миссии, отсутствие снимков до загрузки/в меню и нормальный выход с неизменным исходным профилем.
