# Сетевая телеметрия: технический прототип

## MVP: направление персонажа (2026-11-23)

STATE теперь имеет 36 байт payload / 60 байт вместе с заголовком: после world
Generation идут float32 heading (XY radians, [-pi, pi]) и uint32 heading_valid.
Протокол 3 / модуль 0.0.5 несовместимы с прежним форматом; обе стороны обновлять
вместе. Нулевой heading при heading_valid=1 — настоящий поворот, а не отсутствие
данных. При неизвестном направлении оба поля равны нулю; скорость не используется
для догадки о направлении. Inactive, expiry и disconnect очищают также направление.
NaN, infinity, неверные флаги/диапазон и старый wire формат отвергаются.

Pose API переиспользует существующие session/mailbox; position-only API сохранён
и явно публикует неизвестный heading. Текущий heading передаётся backend через
face, в том числе при неподвижных координатах. Отказ/отсутствие face при известном
heading переводит аватар в штатное удаление. Неизвестный heading не вызывает face.
Smoothing позиции не предсказывает/интерполирует угол; текущая авторизация остаётся
обязательной. Изменение угла при том же packet sequence отвергается как изменение
уже принятого снимка.

Pinned build/audit и пять затронутых production fixtures прошли. Сетевые случаи
handshake, state exchange, expiry, несовместимость и reconnect прошли; mailbox
pose fixture после исправления ожидаемого тестового угла повторён отдельно:
обе стороны приняли heading, inactive и stopped-zero, по 61 полученному снимку.
Это loopback-процессы, не реальная игра или два ПК. Чтение нового visual heading
в игре и нативный face backend ещё не проверены; запуск гостевого аватара закрыт.

Это транспорт и обмен read-only состоянием. Второй игровой персонаж, управление гостя, бой, транспорт, NPC, общий сюжет и host save пока отсутствуют. Локальные тестовые процессы и пассивный приёмник не являются вторым игровым клиентом.

Обновление 2026-11-21: добавлен сетевой контракт согласования мира
[WORLD_AGREEMENT.md](WORLD_AGREEMENT.md), protocol 3 / module 0.0.5.
Реализация скомпилирована, исполнение пока не проверено. Проверенного игрового
producer идентичности мира ещё нет, поэтому разрешение управления остаётся
закрытым. Для применения состояния нужен `CoopNetworkReadRemoteWorld`;
старый `CoopNetworkReadRemote` служит только диагностике координат.

## Реализовано

- ENet 1.3.18 с исправлениями из точного upstream commit `5a9c537fd464b3c6d3c55e1d3bd47588faf71b42`. MIT LICENSE и исходники включены; SHA256 каждого файла проверяется при сборке. Источник: https://github.com/lsalzman/enet/tree/5a9c537fd464b3c6d3c55e1d3bd47588faf71b42
- Прямой IPv4/порт, host на явно выбранном адресе, один guest. Проверка wire protocol, отдельной версии диагностического модуля 0.0.5, SHA256 целевого EXE и набора возможностей. Совпадение версии модуля требуется точно.
- Надёжный channel 0 для HELLO/WELCOME, sequenced unreliable channel 1 для заменяемого состояния. Общий session ID генерируется ОС; player IDs назначаются host: 1 и 2. Локальные GUID и указатели по сети не передаются.
- Явная сериализация в сетевом порядке байтов, фиксированные длины, ограничения ENet на размер пакета/очередь, проверки конечности координат, source player ID/session, sequence и локальной epoch. Epoch не заменяет идентификатор главы или согласованное состояние мира.
- Очистка remote snapshot после отключения, таймаут handshake/соединения, последовательное повторное подключение guest. Автоматического reconnect или пользовательского интерфейса сессии ещё нет.
- Один сетевой worker, созданный вне DllMain. Только worker обслуживает ENet; игровых функций он не вызывает. Два ограниченных буфера последнего снимка отделяют его от игрового callback. Под краткой SRW-блокировкой копируется только память, без сети/файлов/игровых вызовов. Входящий снимок пока только хранится и не применяется к миру.
- Адаптер игрока читает позицию до 20 Гц после game_init + load_finished; диагностический журнал ограничен 2 Гц. В меню/загрузке передаётся inactive. Снимок без обновления 2 секунды также становится inactive; соединение продолжает обслуживаться независимо от игрового потока. Точная производительность ещё не измерена.

## Входящая свежесть: новая версия, проверка исполнения отложена

Раньше две секунды ограничивали исходящий producer, а полученное active-состояние
могло оставаться активным до десятисекундного таймаута соединения. Теперь сессия
запоминает время только **принятого нового STATE** после проверок session/player,
sequence и epoch. Duplicate/stale-пакеты его не обновляют. Через 2000 мс без
нового состояния снимаются remote_active/remote.active и обнуляются координаты;
событие `remote_expired` пишется один раз на такой переход. Соединение при этом
может оставаться ready и принимать следующий корректный пакет. Последовательность
и epoch сохраняются, чтобы поздний старый пакет не восстановил управление.

Буфер `CoopRemoteSnapshot` теперь содержит have_state, received_sequence,
session_id, локальную connection_generation и receiver-local timestamps.
Чтение `CoopNetworkReadRemote` фильтрует копию при каждом обращении:

- Нет worker/запрошен stop: return 0 и полностью нулевой выходной буфер.
- Worker не публиковал буфер 2000 мс либо его timestamp из будущего: тот же отказ.
- Handshake жив, но нет состояния, оно inactive/устарело или metadata/позиция
  недопустимы: return 1 с active=0 и нулевыми координатами.
- Только свежий корректный active-снимок может вернуть active=1.

Проверка при чтении нужна отдельно от worker: зависший worker не сможет сам
снять старое active-состояние. Повторные чтения не продлевают срок данных.
`ready` без `active` не разрешает управление аватаром. Не кэшировать выходной
снимок для последующих кадров без новой проверки свежести.

Время сессии учитывается unsigned-разностью ENet uint32 (с rollover), timestamps
буфера выводятся в локальную монотонную шкалу получателя. Они не отправляются
по сети и не сравниваются между ПК. TTL измеряет время с приёма принятого пакета,
а не неизвестное время его формирования у отправителя. Connection generation
помогает различать повторные подключения на получателе; это **не** chapter ID,
checkpoint ID или согласованная world generation. Wire protocol/формат не менялся.

Полная pinned сборка прошла с warnings-as-errors. Подготовлены, но **не исполнены**
новые проверки сроков state/worker, восстановления, часов/rollover, нулевого
буфера после Stop и двухпроцессный случай, где peer обслуживает ENet, но прекращает
STATE. Пользовательская пауза тестов ради Cyberpunk сохраняется. Не выдавать
старые результаты loopback за проверку этой версии.

Эта логика пока инвалидирует только данные. Физическая остановка/удаление
сетевого аватара на игровом потоке ещё не реализованы и не проверены.

## Запуск

Команды ниже — для возобновления после явного разрешения пользователя;
во время текущей паузы тестов их не запускать.

По умолчанию сеть выключена. Скрипт создаёт opt-in `coop-session.ini` только в конкретном локальном тестовом каталоге.

```powershell
./scripts/build-probe.ps1 -Toolchain <LLVM-MinGW> -OutputDirectory build/network-final
./scripts/test-network.ps1 -BuildDirectory build/network-final
./scripts/start-probe.ps1 -GameDirectory 'D:\Games\Mafia II Classic' -BuildDirectory build/network-final -Observer -SecondScreen -WaitForExit -NetworkRole host -Address 127.0.0.1 -Port 28960
```

Для второго ПК host должен привязаться к своему фактическому IPv4 Radmin; guest указывает этот адрес/порт с `-NetworkRole guest`. Firewall автоматически не изменяется. Этот путь ещё не проверен на двух компьютерах. Не выдавать его за готовое совместное прохождение.

`coop_netcheck.exe guest <IPv4> <port> <duration_ms>` — пассивный диагностический peer, который отправляет только inactive и принимает состояние игры. Он не создаёт фиктивного игрока. Сводка содержит количество активных снимков, диапазоны координат и RTT. При отсутствии активных снимков exit code 4; это не успешная проверка передачи позиции.

## Исторические результаты до новой входящей свежести

- Loopback вне песочницы: два отдельных процесса прошли handshake, двусторонний обмен fixture-векторами, переход в inactive, отказ несовместимым EXE/capabilities и повторное подключение. Отдельная проверка worker/mailbox показала сохранение соединения при остановке producer и сброс устаревшей позиции. Это проверки транспорта, не игровая приёмка.
- В ограниченной сетевой песочнице тот же тест не установил соединение. Без изменения кода за её пределами тест прошёл; первый неудачный результат не скрывается и не считается ошибкой библиотеки.
- Внутри реальной Mafia II observer создал host и отдельный worker. Пассивный диагностический процесс прошёл handshake и получил 598 inactive-сообщений за 5 минут, RTT к концу около 6 мс. Активных координат не было: игра находилась в меню, netcheck вернул 4. Проба выполнена до добавления отдельного поля module version; последний формат проверяется в отдельных процессах. На тот момент полный путь game position → другой процесс ещё не был принят; позднейшие результаты приведены ниже и в TESTING.md.
- Меню действительно просмотрено через Windows computer-use. Первоначальные экземпляры имели high integrity. Запуск `--user` проверен на собственном host (реально medium integrity, ранний DLL, exit 0), затем в игре подтверждён medium integrity. Нажатия автоматизации пока не переключили сюжетное меню; понижение прав само по себе не решило всю проблему. Три собственных диагностических экземпляра в меню принудительно остановлены после проверок/для перезапуска; они не считаются чистыми игровыми выходами. В последней сессии исходный профиль и все 12 baseline-файлов игры не изменились.

## Следующая приёмка

Позднейшие реальные проверки подтвердили меняющиеся координаты после самостоятельного входа и движения Вито; отдельный opt-in Human был создан и удалён. Подробные доказательства и границы версий — в TESTING.md. После разрешения тестов проверить новую входящую свежесть, registry/command guards и остановку будущего remote adapter. До применения remote state по-прежнему нужны host authority, реальная идентификация миссии, согласованная world generation и переходы. Два игровых клиента на разных ПК через Radmin VPN ещё не прошли приёмку.
