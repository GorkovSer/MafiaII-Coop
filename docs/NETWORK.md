# Сетевая телеметрия: технический прототип

Это транспорт и обмен read-only состоянием. Второй игровой персонаж, управление гостя, бой, транспорт, NPC, общий сюжет и host save пока отсутствуют. Локальные тестовые процессы и пассивный приёмник не являются вторым игровым клиентом.

## Реализовано

- ENet 1.3.18 с исправлениями из точного upstream commit `5a9c537fd464b3c6d3c55e1d3bd47588faf71b42`. MIT LICENSE и исходники включены; SHA256 каждого файла проверяется при сборке. Источник: https://github.com/lsalzman/enet/tree/5a9c537fd464b3c6d3c55e1d3bd47588faf71b42
- Прямой IPv4/порт, host на явно выбранном адресе, один guest. Проверка wire protocol, отдельной версии диагностического модуля 0.0.3, SHA256 целевого EXE и набора возможностей. Совпадение версии модуля требуется точно.
- Надёжный channel 0 для HELLO/WELCOME, sequenced unreliable channel 1 для заменяемого состояния. Общий session ID генерируется ОС; player IDs назначаются host: 1 и 2. Локальные GUID и указатели по сети не передаются.
- Явная сериализация в сетевом порядке байтов, фиксированные длины, ограничения ENet на размер пакета/очередь, проверки конечности координат, source player ID/session, sequence и локальной epoch. Epoch не заменяет идентификатор главы или согласованное состояние мира.
- Очистка remote snapshot после отключения, таймаут handshake/соединения, последовательное повторное подключение guest. Автоматического reconnect или пользовательского интерфейса сессии ещё нет.
- Один сетевой worker, созданный вне DllMain. Только worker обслуживает ENet; игровых функций он не вызывает. Два ограниченных буфера последнего снимка отделяют его от игрового callback. Под краткой SRW-блокировкой копируется только память, без сети/файлов/игровых вызовов. Входящий снимок пока только хранится и не применяется к миру.
- Адаптер игрока читает позицию до 20 Гц после game_init + load_finished; диагностический журнал ограничен 2 Гц. В меню/загрузке передаётся inactive. Снимок без обновления 2 секунды также становится inactive; соединение продолжает обслуживаться независимо от игрового потока. Точная производительность ещё не измерена.

## Запуск

По умолчанию сеть выключена. Скрипт создаёт opt-in `coop-session.ini` только в конкретном локальном тестовом каталоге.

```powershell
./scripts/build-probe.ps1 -Toolchain <LLVM-MinGW> -OutputDirectory build/network-final
./scripts/test-network.ps1 -BuildDirectory build/network-final
./scripts/start-probe.ps1 -GameDirectory 'D:\Games\Mafia II Classic' -BuildDirectory build/network-final -Observer -SecondScreen -WaitForExit -NetworkRole host -Address 127.0.0.1 -Port 28960
```

Для второго ПК host должен привязаться к своему фактическому IPv4 Radmin; guest указывает этот адрес/порт с `-NetworkRole guest`. Firewall автоматически не изменяется. Этот путь ещё не проверен на двух компьютерах. Не выдавать его за готовое совместное прохождение.

`coop_netcheck.exe guest <IPv4> <port> <duration_ms>` — пассивный диагностический peer, который отправляет только inactive и принимает состояние игры. Он не создаёт фиктивного игрока. Сводка содержит количество активных снимков, диапазоны координат и RTT. При отсутствии активных снимков exit code 4; это не успешная проверка передачи позиции.

## Фактические результаты

- Loopback вне песочницы: два отдельных процесса прошли handshake, двусторонний обмен fixture-векторами, переход в inactive, отказ несовместимым EXE/capabilities и повторное подключение. Отдельная проверка worker/mailbox показала сохранение соединения при остановке producer и сброс устаревшей позиции. Это проверки транспорта, не игровая приёмка.
- В ограниченной сетевой песочнице тот же тест не установил соединение. Без изменения кода за её пределами тест прошёл; первый неудачный результат не скрывается и не считается ошибкой библиотеки.
- Внутри реальной Mafia II observer создал host и отдельный worker. Пассивный диагностический процесс прошёл handshake и получил 598 inactive-сообщений за 5 минут, RTT к концу около 6 мс. Активных координат не было: игра находилась в меню, netcheck вернул 4. Проба выполнена до добавления отдельного поля module version; последний формат проверяется в отдельных процессах. Полный путь game position → другой процесс ещё не принят.
- Меню действительно просмотрено через Windows computer-use. Первоначальные экземпляры имели high integrity. Запуск `--user` проверен на собственном host (реально medium integrity, ранний DLL, exit 0), затем в игре подтверждён medium integrity. Нажатия автоматизации пока не переключили сюжетное меню; понижение прав само по себе не решило всю проблему. Три собственных диагностических экземпляра в меню принудительно остановлены после проверок/для перезапуска; они не считаются чистыми игровыми выходами. В последней сессии исходный профиль и все 12 baseline-файлов игры не изменились.

## Следующая приёмка

Подтвердить исправленное ожидание загрузки и реальную передачу меняющейся позиции, затем идентификацию миссии и создание/удаление отдельного персонажа. До применения remote state нужны правила host authority, согласованная world generation и переходы. Обязательная проверка на двух ПК через Radmin VPN остаётся открытой.
