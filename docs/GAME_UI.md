# Управление интерфейсом игры

Пользователь передал агенту управление и тесты. Рабочий ввод — нативные scan codes
через `coop_input`; обычные `sky.press_key` со стрелками/Return давали сообщения
окна, но не игровые события DirectInput. Не повторять эту диагностику.

## Быстрый вход — основной способ

По прямому указанию пользователя повторять Enter со стартового меню до начала
загрузки. Не ждать отдельного анализа каждого готового меню. Скрипт:
`scripts/enter-story.ps1`.

1. Запустить `start-probe.ps1 -Observer -WaitForExit` с нужной готовой сборкой
   и `-TestProfileFrom <earlier-test-id>`. Не использовать `-ContinueMainStory`:
   сейв загружается обычным меню.
2. Взять PID из `probe_loaded pid=...` и ID именно этой сессии.
3. Через computer-use `sky.list_windows()` выбрать единственное возвращённое
   окно `mafia2.exe`, получить его через `get_window` и активировать.
4. Сразу запустить:

```powershell
./scripts/enter-story.ps1 -SessionId <current-session-id> -GamePid <launcher-pid> -BuildDirectory build/human-settled-test
```

Скрипт сверяет PID с журналом/launcher, требует изолированный профиль и отсутствие
предыдущей загрузки, проверяет SHA256 EXE и creation через native helper.
Повторяет Enter: удержание 100 мс, промежуток 200 мс с опросом журнала каждые 50 мс.
Каждое нажатие проверяет живой процесс/creation/foreground.
На первом `load_started` или открытии миссии **навсегда прекращает ввод** и ждёт
`load_finished` плюс `player_sample`. Лимит меню 30 секунд, загрузки 60 секунд.
При ошибке или потере фокуса ввод прекращается; перед повтором наблюдать окно.

Проверенный путь: логотип → THE STORY → **CONTINUE STORY / «Продолжить сюжет»**.
Он рассчитан на известный профиль со стандартным начальным выделением.
Если профиль/меню изменились, есть неожиданный диалог или сценарий не загрузился,
наблюдать экран и перейти к пошаговому режиму. Повторный запуск в уже загруженной
сессии запрещён самим скриптом. Не запускать параллельных отправителей ввода.

После возврата скрипта сделать один снимок сцены с Вито и HUD.
Телеметрия сама по себе не заменяет визуальное подтверждение.
Для создания Human отдельно выдерживается установление позиции по HUMAN_TEST.md.

## Быстрый выход — основной способ

Пользователь потребовал **Enter сразу после Alt+F4**, без снимка/ожидания диалога
между ними. Сфокусировать собственное диагностическое окно, затем:

```powershell
./scripts/exit-game.ps1 -SessionId <current-session-id> -GamePid <launcher-pid> -BuildDirectory build/human-settled-test
```

Скрипт проверяет принадлежность сессии и вызывает `coop_input quit PID CREATION`.
Нативный помощник до ввода проверяет полный EXE, creation, живой процесс и фокус;
одним вызовом отправляет Alt+F4 и **сразу** начинает Enter.
Лимит повторов — 5 секунд, Enter удерживается 100 мс с промежутками до 50 мс.
При выходе процесса или потере фокуса новые нажатия прекращаются.
Исчезновение окна может опережать сигнал процесса: после него помощник до секунды
ждёт native handle, уже без ввода. Никакого force-close.

Дождаться завершения launcher и проверить `launch-result.json`:
native child exit 0 и ноль изменений исходного профиля.
Время нативного выхода не включает накладные расходы инструментов/проверку профиля.
Не запускать новую игру, пока предыдущий процесс жив.

## Пошаговый режим и движение

Перед Windows UI читать установленный skill computer-use и его документацию.
Для выбора окна/фокуса/снимков использовать sky. После сброса node_repl снова
импортировать `@oai/sky`, не использовать старое окно завершённого процесса.

`coop_input inspect PID` возвращает creation, затем:
`coop_input key PID CREATION up|down|left|right|enter [hold_ms]`.
Срок удержания 50–2000 мс, по умолчанию 100 мс.
В меню Up/Down меняют выделение, Enter подтверждает. На стандартном пути
все нужные пункты уже выделены: стрелки не нужны. Не выбирать Load Chapter/New Game.
В игре Up действительно двигает Вито; проверено удержание 1000 мс.
После ограниченного движения наблюдать сцену/координаты.
Нельзя ориентироваться на системный курсор: игровой курсор отдельный.
Escape через sky не открыл паузу.

В пошаговом режиме объединять одно нативное нажатие и последующий
`sky.get_window_state({window, include_text:false})` в один последовательный
`functions.exec`. Проверять код native helper до снимка; сохранять возвращённое
`state.window`. Не выполнять независимую работу между готовым меню и действием.
При неизвестном результате сначала наблюдать, а не повторять нажатие.

Полный экран разрешён позднейшим указанием пользователя. Видео менять только
в изолированном профиле; окно на втором мониторе включается `-SecondScreen`.
Не перестраивать неизменённый код, не повторять inspect/list_windows/Down-Up
между пунктами и не выводить уже показанные снимки второй раз.

SendInput — системный ввод: проверка foreground не атомарна со сменой фокуса.
Помощник проверяет фокус во время удержания и всегда пытается отпустить клавишу.
Пользователь явно разрешил нативные стрелки/Enter и затем немедленный Alt+F4 → Enter
для наших тестов; это исключение из обычного пути skill, не повод спрашивать снова.

через 3,256–5,355 с от начала серии Enter (не от запуска EXE).
Сцена с нужным сейвом подтверждена снимками.
Немедленный нативный Alt+F4 → Enter из сюжета завершил процесс за 2,765 с,
native exit 0, исходный профиль не изменился.
Эти числа не включают запуск инструмента, активацию окна и пересылку снимков.
Два реальных сетевых клиента этим тестом не проверялись.
