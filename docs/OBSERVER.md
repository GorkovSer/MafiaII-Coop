# Наблюдатель событий: эксперимент 0.0.2

Это проверочный компонент этапа 1. Кооператив и сюжетные адаптеры ещё не реализованы. На целевом GOG EXE подтверждены реальные callbacks меню; сюжетные callbacks ещё проверяются.

## Реализовано

- Ранняя загрузка DLL при приостановленном основном потоке. Реальный test host различает выполнение до/после входа в WinMain; для раннего режима получено `test_host_entry_seen=0` и нормальное завершение.
- Модули определяются с учётом ASLR. До готовности PEB module list используется обход отображённых MEM_IMAGE через VirtualQueryEx/GetMappedFileName. Для инициализации loader используется временный поток, завершающий только себя через системный экспорт RtlExitUserThread. Проверено на текущей Windows; переносимость на другие Windows ещё не установлена.
- Наблюдатель отказывает неизвестному EXE по полному SHA256 и изменённым сигнатурам двух участков. Массовая инициализация SDK не вызывается.
- Один стартовый JMP в памяти переводит выполнение на регистрацию наблюдателя. В callback восстанавливаются исходные пять байт, сохраняются регистры/флаги и выравнивается стек для собственного C-кода.
- Регистрируются callbacks тиков, загрузок, открытия/закрытия миссии, game init/done/restore/save. Они не меняют мир. Для частых событий логируется только первый вызов; thread IDs фиксируются отдельно.
- Экспериментальный redirect CSIDL_LOCAL_APPDATA через импорт SHGetFolderPathA действует только внутри тестового процесса. Он не меняет системную настройку или настоящий каталог профиля. Перед тестом копия Data/Saves помещается в `work/probe-sessions/<session>/profile-localappdata/2K Games/Mafia II`.

Изоляцию сохранений нельзя считать доказанной только по установленному IAT hook. Для Mafia II нужны запись `profile_local_appdata_redirected=1`, созданные игровые данные именно в копии профиля и сравнение оригинальных файлов до/после. До этих проверок не выполнять сюжетные действия с автосохранением.

## Запуск

Закрыть предыдущую диагностическую игру обычным выходом. Запуск при существующем процессе Mafia II запрещён скриптом. Не завершать пользовательскую игру принудительно ради теста.

```powershell
./scripts/build-probe.ps1 -Toolchain <LLVM-MinGW> -OutputDirectory build/probe-next
./scripts/test-probe.ps1 -BuildDirectory build/probe-next
./scripts/start-probe.ps1 -GameDirectory 'D:\Games\Mafia II Classic' -BuildDirectory build/probe-next -Observer -SecondScreen -WaitForExit
```

Отдельная output directory позволяет собирать новую версию, пока DLL предыдущей версии загружена в игру; занятые DLL не перезаписываются.

По указанию пользователя игровые тесты запускаются в окне на DISPLAY2. `-SecondScreen` задаёт 1280×720/windowed только в копии videoconfig.cfg; загрузчик размещает окно на втором экране и проверяет монитор. При отсутствии DISPLAY2 запуск запрещён. Проверено фактическое окно с client size 1280×720 на DISPLAY2. Исходный профиль при первой проверке после запуска совпал с backup. После выхода скрипт повторно сравнивает хеши исходных профилей, включая добавленные/удалённые файлы; результат остаётся локально.

## Приёмка эксперимента в игре

1. Зафиксировать новую сборку, хеш EXE, backup и исходные хеши оригинальных Data/Saves.
2. Получить `startup_hook_installed`, затем `startup_hook_restored` со значением 1 и успешные результаты AddAction.
3. Получить реальные события и сравнить thread IDs регистрации/вызовов. Принятие AddAction не доказывает, что callback вызывался.
4. Подтвердить видимое меню; сначала проверить изоляцию профиля без прохождения миссии.
5. Только после проверки изоляции проверить обычную загрузку миссии, menu/pause/load transitions и выход. Сопоставить действия с логом.
6. Сравнить оригинальные Data/Saves и EXE/DLL, записать код завершения. Не публиковать личные профили или сырые логи.

Для удаления закрыть процесс: игровые файлы на диске не меняются, in-memory hook и импорт существуют только внутри тестового процесса. Тестовые Data/Saves остаются отдельно. Не заменять ими оригинальные сохранения.
