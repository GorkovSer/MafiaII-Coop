# Сборка согласованного preview

Новый механизм написан без запуска по просьбе пользователя. До проверок это
код для следующей сборки, не подтверждение готовности существующего ZIP.

## Что сохраняется

build-probe.ps1 и build-launcher.ps1 создают build-provenance.json в своих
выходных каталогах. В нём относительные пути и SHA-256 входных файлов, тип
сборки, признак завершения и SHA-256 распространяемых DLL/EXE. Исходники
фиксируются до компиляции и повторно сверяются после неё. Неуспешный запуск
не оставляет новый complete=true. Тесты и успешный игровой запуск этим полем
не подтверждаются: оно описывает только завершение сборки.

## После разрешения сборки и тестов

1. Сохранить исходники коммитом. Забрать согласованные изменения соавтора.
2. Собрать native runtime через scripts/build-probe.ps1 с закреплённым Toolchain
   в отдельный OutputDirectory, затем frontend через scripts/build-launcher.ps1.
3. Выполнить необходимые проверки новой части и общей интеграции.
4. Запустить scripts/package-visual-mvp.ps1 с явными BuildDirectory и
   FrontendDirectory. Рабочая копия должна быть чистой.
5. Обоим игрокам передать один и тот же полный ZIP с его SHA-256.

Упаковщик отказывает при отсутствии provenance, complete=false, изменении
исходников или несовпадении хешей бинарников. Он дополнительно сверяет копии
DLL/EXE уже в staging и исходный commit/чистоту перед созданием ZIP. Оба
provenance JSON включаются в общий manifest. Старый build без metadata нужно
пересобрать; задним числом создавать metadata для него нельзя.

## Что проверить при приёмке механизма

- Чистые runtime/frontend builds и упаковка согласованного набора.
- Старый build без metadata и оборванная сборка.
- Изменение runtime исходника, включая remote_timeline соавтора.
- Замена DLL/EXE после сборки и во время копирования в staging.
- Изменение входного файла во время компиляции и смена commit при упаковке.
- Нет записи абсолютных личных путей в распространяемый provenance.

Это защита от случайного смешивания версий, не замена подписи релиза или
внутриигровой проверки обоих клиентов.

Regression runner: scripts/test-build-provenance.ps1. Проверяет также runtime
launcher sources из src/launcher: probe_launcher.c, window.c, user_process.c
входят в runtime provenance; только frontend.c/manifest исключены из runtime.
Старая запись, построенная с исключением всей этой папки, больше не принимается.
