# Простой лаунчер подключения — черновик

Предыдущий вариант окна пользователь показал на скриншоте вместе с CMD.
Новая версия с EXE, другим оформлением и фиксированным портом подготовлена
**без открытия интерфейса, игры и функциональных тестов**; её приёмка ещё впереди.
Игровой runtime не изменён.

После разрешения на проверку: распаковать полный архив в короткую папку,
например `C:\MafiaCoop`, и открыть `MafiaII-Coop.exe` двойным щелчком.
Один архив нужен обоим игрокам; исходников GitHub без собранного DLL недостаточно.

- **Хост:** выбрать «Хост», свой IP из Radmin, папку Mafia II Classic и нажать
  «Создать сессию и запустить игру». Передать этот IP другу.
- **Гость:** выбрать «Гость», ввести IP хоста, выбрать свою папку игры и нажать
  «Подключиться и запустить игру». Порт фиксирован: 28960, настройки порта нет.
- Оба входят в одну сеть Radmin. В игре — два Escape для интро, затем штатное
  «Продолжить». Скрипт создаёт отдельный профиль из контрольного сейва. Один игрок
  отходит от общей точки появления; соединение и показ модели делает существующий
  мод. Текущий сейв хоста не передаётся; общие миссии/бой ещё не реализованы.

Окно лаунчера — отдельная программа перед игрой. Меню Mafia II не изменяется.
Visual preview запускается в окне 1280×720 через настройки отдельного тестового
профиля; исходные видео-настройки пользователя не меняются.
Параметры передаются worker через JSON, без подстановки IP/пути в shell-команду.
Штатный start-visual-session сохраняет проверки EXE, manifest, профиля и одной игры.
Диагностические обходы второго экземпляра и фоновой паузы не включаются.
Запуск скрипта не выдаётся за подтверждённое сетевое соединение.

Лаунчер показывает состояние текущей сессии: ожидание друга, соединение до
загрузки, ожидание активной сцены, создание аватара, паузу, потерю связи и
автоматическое переподключение гостя. Указание гостем собственного локального
IPv4 отклоняется с подсказкой использовать адрес хоста. При перезапуске задания
показывается необходимость нового preview у обоих; отказ совместимости не
выдаётся за обычное ожидание. Статус основан на журнале, не заменяет проверку
видимости второго игрока на обоих экранах.

Кнопка «Найти» проверяет стандартные Games каталоги готовых локальных дисков
и библиотеки Steam из libraryfolders.vdf, без рекурсивного поиска по диску.
При нескольких установках выбирается EXE с закреплённым SHA-256. Отсутствие
игры в этих местах не означает, что она не установлена: остаётся ручной выбор.
В поле пути допустимы корень игры, каталог pc или полный путь к mafia2.exe;
перед запуском путь нормализуется, EXE проверяется. Игра и библиотеки не меняются.

Worker атомарно связывает запуск с конкретным session_id через session-info.json.
Лаунчер читает только этот журнал последовательно, максимум 64 КБ за тик, без
сканирования старых сессий. Закрытие окна по-прежнему не завершает игру.
После выхода worker автоматически сохраняет session-report.json и проверяет
child/launcher exit, неизменность исходного профиля и баланс моделей, если они
создавались. Выход без друга допустим, но не называется успешным показом аватара.

Настройки: `work/launcher-settings.json`. Журналы запуска:
`work/launcher-runs/<ID>/request.json`, `output.txt`, `result.json`.
Полные игровые отчёты остаются в `work/probe-sessions/<ID>`.
Кнопка «Крашлоги» всегда доступна и открывает `work/crashlogs`, создавая папку,
если её ещё нет. Туда записываются JSON-отчёты ошибок лаунчера и запуска/выхода
сессии: сообщение исключения, стек PowerShell и путь к журналу соответствующего
запуска. Это диагностические отчёты, а не нативные minidump игры. Не обещать
автоматический сбор всех WER/движковых крашлогов. Галка второго монитора удалена;
старое сохранённое поле second_screen игнорируется и больше не передаётся worker.
Это локальные приватные файлы; не публиковать их целиком на GitHub.
Закрытие окна освобождает только handle процесса, не завершает worker/игру.
В черновой версии повторное открытие того же preview восстанавливает наблюдение
за worker из work/active-launcher-run.json, сверяя PID, время создания и системный
путь процесса. Новую игру такое открытие не запускает. Старая ссылка с уже
завершённым или переиспользованным PID не используется. Проверка этой функции
запуском пока отложена пользователем.
Отдельный session-state.json сообщает этап подготовки, реального запуска и
проверки выхода. Worker возвращает код причины сбоя, а UI — русскую подсказку.
Чтение маленьких JSON ограничено по размеру и допускает атомарную замену файла.
В черновой реализации лимит действует и при росте файла во время чтения;
повреждённая UTF-8, пустой JSON и корневой массив/скаляр отклоняются.
Session link записывается тем же атомарным writer с уникальным временным именем.
Эти изменения пока проверены только чтением исходников, без исполнения.
Временная ошибка чтения статуса повторяется, без закрытия игры; диагностический
отчёт о ней пишется один раз за запуск. Отсутствие итогового отчёта не считается
успешным выходом, даже если worker уже завершился.
Проверки и исходные сохранения выполняются до завершения worker даже без окна.
Workers разных копий preview используют общую блокировку запуска для текущего
пользователя Windows. Второй запуск отклоняется, пока первый готовит профиль,
играет или завершает проверку результата; никакие процессы не закрываются.
Новый механизм блокировки пока написан без функциональных тестов по просьбе
пользователя и не имеет отдельной приёмки.

Разработчику из исходников: явно передать каталог своей собранной версии:
`./scripts/coop-launcher.ps1 -BuildDirectory build/visual-pair-20261127`.
В переносимом архиве каталог берётся из manifest; вручную файлы не перемешивать.
Нативный GUI entry point собирается `scripts/build-launcher.ps1 -Toolchain <путь>`
в build/launcher/MafiaII-Coop.exe, затем переносится упаковщиком в корень архива.
Это PE Windows GUI subsystem с оригинальной иконкой и manifest asInvoker.
Он запускает Windows PowerShell STA через CREATE_NO_WINDOW, направляет вывод в
work/crashlogs/bootstrap-*.txt и оставляет первое окно WinForms видимым.
CMD больше не входит в архив. Окно оформлено без игровых ресурсов: белая serif
типографика, тёмный градиент, тонкая геометрическая рамка и красные акценты.
Execution policy задаётся только дочернему процессу, настройки Windows не сохраняются.
Старые поля port/second_screen из настроек и request не влияют на запуск:
worker передаёт только фиксированный порт 28960, параметра монитора нет.

Когда пользователь разрешит тесты, проверить одним блоком:

1. Открытие/DPI/кириллица, обе роли, список IP, ввод и выбор папки, сохранение
   настроек. Неверный IP/чужой IP хоста/неверный путь/неполный архив — понятный отказ.
   Новый EXE открывает только окно лаунчера без консоли; запуск от администратора
   не требуется. Иконка и окно корректно масштабируются; выбор порта отсутствует.
2. Реальный запуск каждой роли в изолированном профиле,
   доступный журнал и восстановление кнопки после штатного выхода/ошибки.
   «Крашлоги» доступны до первой сессии; ошибка worker сохраняет JSON-отчёт.
   Проверку на втором мониторе согласовать отдельно; в пользовательском GUI
   управления монитором больше нет, диагностический CLI остаётся отдельным.
3. Закрыть лаунчер при работающей игре: игра продолжает работать, worker сохраняет
   итоговый отчёт; повторный лаунчер не обходит защиту уже запущенной Mafia II.
4. Два разных ПК/Radmin: видимые модели, движение/поворот, пауза, выход/повторный
   вход. Сопоставить обе записи экрана и журналы; затем обновить отметку проверки.
